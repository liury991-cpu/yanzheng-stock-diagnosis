# 言证 YanZheng｜AI 个股多维诊断

言证是一个证据优先的 AI Native 个股研究工作台。本次演示标的是美的集团（000333.SZ）。产品不输出“好/坏”标签或买卖建议，而是让用户从结论回到原始字段、计算口径和来源，并明确区分事实、分析推断与暂时无法验证的信息。

## 在线体验

- Web 产品：https://liury991-cpu.github.io/yanzheng-stock-diagnosis/
- 源代码：https://github.com/liury991-cpu/yanzheng-stock-diagnosis
- 演示标的：美的集团（000333.SZ）
- 数据基准：2025 年年度报告；估值为 2026-09-18 第三方演示快照

## 核心体验

1. 用户用自然语言提出研究问题，系统按关键词和公司类型选择优先诊断维度。
2. 结果先给“可证伪的综合判断”，再展示正面、负面、矛盾和未知四类证据。
3. 点击证据卡可下钻到原始字段、财务期次、计算公式、来源页和下一步验证动作。
4. 数据不足或接口未接入时保持“未知”，不会用模型常识补出行情、估值分位或同行排名。

建议依次尝试四个问题：

- 利润增长为什么快于收入？
- 增长主要由什么驱动？
- 当前估值能否判断高低？
- 最大的反证是什么？

## 产品选择

### 为什么选择美的集团

美的是多元制造公司，既有智能家居基本盘，也有海外业务和 ToB 第二曲线。2025 年收入与利润增长、经营现金流回落、制造业务毛利率微降同时发生，天然适合展示“证据并不总同向”的诊断体验。

### 为什么不是通用聊天框

金融研究的核心风险不是文案不流畅，而是口径混用、数字失真和推断越界。因此主链路是“问题路由 → 确定性计算 → 证据光谱 → 结论下钻 → 待验证清单”，聊天只是入口。

## AI、程序与人的分工

| 环节 | 负责方 | 边界 |
| --- | --- | --- |
| 原始数据读取 | 数据适配器 / 程序 | 保留 source、as_of、unit、period、scope |
| 同比、利润率、分位 | 确定性计算 | 统一单位与期次；缺字段即失败，不猜值 |
| 问题路由、矛盾识别、解释 | LLM | 只能引用已绑定的 evidence_id，不直接计算关键数字 |
| 数值与引用校验 | 规则引擎 | 回算数字、检查来源时点、拦截无引用结论 |
| 最终判断 | 用户 | 沿证据继续研究，不接受买卖指令 |

本演示不依赖在线 LLM，采用可复现的问题路由和证据合成器，确保无需 API Key 也能完整操作。生产版可在相同证据协议上替换为结构化输出的 LLM。

## 数据来源

- 美的集团 2025 年年度报告：主要会计数据、现金流、分部/地区收入、研发投入、重要事件与风险。
- 理杏仁估值页：仅作为 2026-09-18 演示快照；不把第三方单点快照包装成历史估值结论。
- 扶摇金融数据 API：生产方案中的行情、交易日历、板块成分、历史估值和同行财务适配器；本地演示未取得授权，因此相关卡片明确显示“待验证”。

关键数字都可在产品证据抽屉中查看来源、时点、单位与计算公式。

## 技术架构

- Vinext / React 19 / TypeScript
- 单页交互式 Web 产品，Cloudflare Worker 兼容构建
- 静态证据集 + 确定性路由，便于评审复现
- 无数据库、无用户数据、无外部密钥

生产数据协议建议：

```ts
type Evidence = {
  id: string;
  claim_type: "fact" | "inference" | "unknown";
  sentiment: "positive" | "negative" | "conflict" | "unknown";
  raw_fields: Array<{ name: string; value: number | null; unit: string }>;
  formula?: string;
  source: { url: string; title: string; page?: string };
  as_of: string;
  scope: string;
};
```

## 已知边界与未做事项

- 未取得扶摇 / iFinD 授权，行情区间、历史估值分位和同行对比保持未知。
- 当前仅演示美的集团，尚未实现输入任意股票代码后的动态数据采集。
- 年报页码按 PDF 阅读器显示可能存在 1–2 页偏差，因此同时保留章节名。
- 第三方估值快照与年报时点不同，界面明确标注，未作跨时点强因果解释。
- 未实现登录、关注列表、持仓画像和投资建议，避免引入隐私与合规风险。
